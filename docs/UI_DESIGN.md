# DSH Launcher 最终设计稿

> 本文档是安装、卸载、首页、更新页和设置页的唯一产品设计基准。
> 旧实现或旧文档若与本文冲突，以本文为准；代码中已存在的页面不等同于已经验收。

## 1. 产品边界

DSH Launcher 是 Windows 优先的一体化 DSH 管理器：安装 DSH、安装或复用
Node.js、启动/停止/打开 DSH、更新 DSH 与启动器、查看日志、卸载启动器管理
的组件。默认面向国内无代理用户，国内镜像优先，不弹终端窗口，不误删用户数据。

全局规则：一个时刻只执行一个管理操作；普通通知在右上显示 5 秒且不阻挡点击；
需要选择的确认窗为居中模态窗。主色为蓝色，成功为绿色，取消和危险操作为红色。
页面使用浅灰背景、白色圆角卡片、清晰留白。运行详情使用可滚动列表，最多显示
100 条关键事件，完整日志写入 `%LOCALAPPDATA%\\DshLauncher\\logs`。

顶部使用应用图标和 `DSH Launcher`，右侧显示启动器版本。已安装 DSH 时首页右上
显示小型 Fluent 六齿轮设置入口；未安装 DSH 时不显示设置。子页使用圆角方形的
左尖括号返回按钮。下拉菜单是文字区加箭头区的 split button，默认向下展开。

## 2. 状态与启动规则

```text
检测
  ├─ DSH 未安装 -> 首次安装流程
  └─ DSH 已安装 -> 首页

首页 -> 启动 / 停止 / 打开网页 / 检查更新 / 设置
首次安装 -> 完成页 -> 关闭窗口后打开一次网页
更新页 -> 更新 / 校验 / 重启 DSH -> 首页
设置页 -> 日志诊断 / 安装与管理 / 卸载确认
```

DSH 已安装时，双击启动器先启动或复用 DSH 服务，并在服务就绪后自动打开一次网页；
更新在后台检查。没有更新时启动器自动隐藏或 30 秒后关闭，DSH 服务继续后台运行。
有更新时显示更新选择窗。网络检查失败时必须显示“更新检查未完成”，不得说成
“已是最新”。“启动 DSH”按钮只启动服务，绝不再次触发更新检查。

## 3. 首页

### DSH 已停止

```text
● DSH 已停止
需要时点击“启动 DSH”

[ 启动 DSH ]                         [ 检查更新 ]
```

### DSH 正在运行

```text
● DSH 正在运行
服务已就绪，可打开网页或停止服务

[ 打开 DSH 网页 ] [ 停止服务 ] [ 检查更新 ]
```

“打开 DSH 网页”只打开 `http://127.0.0.1:3080`；停止服务只允许停止启动器记录
的进程。3080 端口由非启动器进程占用时，必须说明并拒绝误杀。

首页不显示下载源、更新操作和卸载。运行详情卡片保留边距，不允许叠字或重复刷屏。

## 4. 首次安装：未安装 DSH

未安装时不进入普通首页，也不显示设置或检查更新。先显示检测结果页：

```text
● 检测到尚未安装 DSH
DSH 需要 Node.js 与 npm 才能运行。

[ 取消 ] [ 开始安装 ] [ 一键安装！ ]
                         懒人必备，一步到位
```

“取消”关闭启动器且不改动系统。“一键安装”选择 DSH 默认目录、Node.js 默认目录
`C:\\Program Files\\nodejs`、Node.js 国内镜像和 DSH 国内 npm 镜像；缺少 Node.js
时请求 Windows UAC 授权。

### 4.1 DSH 目录

```text
选择 DSH 安装目录
默认目录适合大多数用户；自定义目录会保留在该位置。

[ 默认目录 ] [ 自定义目录 ] [ 上一步 ]
```

记录最终 `dsh.cmd` 的精确路径；后续启动、更新和卸载以该路径为准，不能依赖 PATH。

### 4.2 Node.js 检测与说明

已有完整 Node.js/npm 时：

```text
Node.js 已就绪
检测到可用的 Node.js 与 npm，将直接安装 DSH。

[ 开始安装 ] [ 重选目录 ] [ 上一步 ]
```

缺少 Node.js/npm 时，先说明 Node.js 是 DSH 运行基础，包含 node 与 npm，缺少时
DSH 无法安装和启动；随后进入来源页。

### 4.3 Node.js 来源

```text
选择 Node.js 下载源
国内镜像适合中国大陆网络；官方源通常需要稳定的国际网络。

[ 国内镜像（推荐） ] [ 官方源 ] [ 上一步 ]
```

| 选项 | 实际来源 |
| --- | --- |
| 国内镜像 | `https://npmmirror.com/mirrors/node/` |
| 官方源 | Node.js 官方/winget `OpenJS.NodeJS.LTS` |

### 4.4 Node.js 目录

```text
选择 Node.js 安装位置
Node.js 会作为系统运行环境安装，供 DSH 使用。

[ 默认目录 ] [ 自定义目录 ] [ 上一步 ]
```

默认目录为 `C:\\Program Files\\nodejs`。启动器记录实际 Node.js 目录，后续 npm、
启动和更新优先使用记录目录，不依赖 PATH 即时刷新。

### 4.5 管理员授权

```text
需要管理员授权
将通过 Windows 安装器安装 Node.js LTS。系统会显示 UAC 确认；
同意后继续安装 Node.js，再通过国内 npm 镜像安装 DSH。

[ 授权并安装 ] [ 取消 ] [ 上一步 ]
```

不得静默提权。拒绝 UAC 时，明确告知 Node.js 和 DSH 均未安装。MSI 已运行时不能
粗暴杀掉安装器；取消只能取消后续 DSH 安装。

### 4.6 安装中与完成页

安装中显示明确阶段和已用时间，npm/DSH 下载期间提供红色“取消安装”。无法取得
字节进度时不得伪造下载速度，而应显示当前真实阶段。

完成页：

```text
● DSH 安装完成
服务已准备就绪。关闭启动器后将自动打开 DSH 网页。

[ 打开 DSH 网页 ] [ 关闭启动器 ]
```

关闭或 30 秒自动关闭时最多打开一次网页。

## 5. 更新检查与更新页

首页“检查更新”手动检查 DSH 和启动器。两者均无更新时用非阻塞通知显示：

```text
已完成更新检查
DSH 与启动器均已是最新版本
```

有更新时显示模态选择窗：

```text
发现可用更新
DSH：当前版本 -> 最新版本
启动器：当前版本 -> 最新版本/已是最新

[ 进入更新 ] [ 稍后更新 ]
```

“稍后更新”回首页，不应再次自动跳回更新页。

更新页：

```text
[ <- ]  更新                                      v启动器版本
        选择更新内容后开始下载与校验

可用更新                                      [ 展开更新说明 ]
DSH       当前版本                         -> 最新版本
启动器    当前版本                            已是最新/最新版本

[ 国内镜像                     v ] [ 一键更新                     v ]

[ 取消并返回首页 ]
```

下载源只在更新页出现：`国内镜像（默认）/ 官方源`。更新操作下拉包含：
`一键更新 / 仅更新 DSH / 仅更新启动器`；一键更新为蓝色主按钮，其余为蓝灰色。
所有取消更新按钮为红色。

DSH 更新必须：读取实际原安装路径与版本；按所选源检查版本；停止由启动器管理的
DSH 后确认 3080 已释放；在原目录更新；重新读取版本校验；校验成功才启动服务。
失败页必须给出明确阶段、重试和返回首页，日志记录 URL、HTTP/WinHTTP 错误、npm
输出摘要、超时、取消和校验结果。

启动器更新默认使用 Gitee Release，官方源使用 GitHub Release。必须有正式清单、
文件大小和 SHA-256；无有效清单时只能显示“更新源尚未配置”，不能伪造最新状态。

## 6. 设置页

仅在 DSH 已安装时可进入：

```text
[ <- ] 设置
       日志、诊断与安装维护

左侧：通用 / 日志与诊断 / 安装与管理 / 关于
右侧：所选分区的说明和操作
```

### 通用

说明启动和更新分离；下载源仅能在更新页选择。

### 日志与诊断

展示日志说明及“打开日志目录”。日志位置：
`%LOCALAPPDATA%\\DshLauncher\\logs\\launcher.log` 和 `dsh-web.log`。日志需轮转、
清理过期文件、脱敏密钥和会话内容。

### 安装与管理

显示 DSH 目录、DSH 当前版本、Node.js 目录、Node.js 版本、npm 版本；提供：

```text
[ 打开 DSH 安装目录 ] [ 重新检测环境 ]

危险操作
[ 卸载 DSH ]                 红色
[ 卸载 DSH + Node.js ]       红色
```

设置页不显示下载源。

### 关于

显示启动器当前/最新版本、DSH 当前/最新版本、Node.js/npm、Windows 架构和日志目录。

## 7. 卸载流程

卸载必须重做，不能保留旧的“三按钮直接删除”体验。

### 卸载 DSH 确认

```text
卸载 DSH？
将删除：当前记录的 DSH 程序文件与依赖。
默认勾选：[x] 保留对话记忆（推荐）
取消勾选时仅清除 `DSH_HOME\\sessions` 与 `DSH_HOME\\storages`；
DSH 配置、账号凭据、profiles 与日志始终保留。

[ 取消 ] [ 确认卸载 DSH ]
```

执行时先停止启动器管理的 DSH，校验记录目录，只删除该目录中的 DSH 文件，删除
路径记录；不得按模糊名称递归删除用户目录。

### 卸载 DSH + Node.js 确认

```text
卸载 DSH 与 Node.js？
将删除：当前记录的 DSH，以及由本启动器安装并记录的 Node.js。
若 Node.js 不是由启动器安装或可能被其他软件使用，将不提供自动卸载。
默认勾选保留对话记忆；取消勾选时的清理范围同上。

[ 返回 ] [ 确认卸载 ]
```

只允许卸载启动器安装且记录了来源/目录的 Node.js；用户已有 Node.js 不得自动卸载。
系统 Node.js 必须通过 Windows Installer/winget 卸载，不能直接删目录。

完成页必须分别说明已删除和保留的内容，并提供打开日志目录和关闭操作。

## 8. 网络、取消与性能

国内用户默认使用 npmmirror：DSH 为 `https://registry.npmmirror.com`，Node.js 为
`https://npmmirror.com/mirrors/node/`；官方源分别为 npmjs 与 Node.js 官方/winget。
网络失败必须区分 DNS、443 不可达、系统代理、TUN、TLS、HTTP 和 npm 错误。

外部命令隐藏执行，纳入 Job Object，限制 npm 内存与并发。安装/更新前检查可用内存。
取消立即阻止新网络任务和文件覆盖，等待当前受管任务安全退出；不得长时间停留在
“正在取消”。设置可浏览但忙碌时禁止产生冲突的管理操作。

## 9. 发布验收

发布前至少验证：无 DSH/无 Node.js 的国内镜像一键安装；已有 Node.js 的默认和自定义
DSH 安装；Node.js 自定义目录后启动/更新；原 DSH 目录更新；网页只打开一次；停止、
取消、断网、更新失败均有确定结果；卸载保留用户数据且不删用户 Node.js；各 DPI 下无
叠字、遮挡或错位；启动器 Release 自更新完成真实 SHA-256 验证。
